# ORAG v0.2 Completion and Windows Distribution Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task (the owner chose native execution: the orchestrator implements every task itself). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish the ORAG engine and its built-in web page for v0.2.0 (the remaining roadmap items, honest evaluation, the model decision), then ship a Windows build that a non-technical user can install, set up offline and run.

**Architecture:** The single `orag` binary stays the product (D-001). v0.2 adds page provenance to chunks and citations, an advisory PDF layout warning, a 10 MB default limit, a *setup mode* in which `orag serve` starts without models and the page imports offline packs, and an `orag start` launcher that supervises `orag serve` and opens the page. Windows support reuses the same code with Windows-specific process isolation (a Job Object instead of process groups and rlimits), static CRT linking and an Inno Setup per-user installer built in CI.

**Tech Stack:** Rust 1.98.1, axum 0.8.9, tokio 1.53, rusqlite (bundled) + FTS5 + sqlite-vec =0.1.9, llama-cpp-2 =0.1.158 (Metal on macOS, CPU elsewhere), pdf_oxide =0.3.78, plain HTML/CSS/ES modules for the page, `windows-sys` for Job Objects, Inno Setup 6 for the installer, GitHub Actions (macos-15, ubuntu-22.04, windows-2022).

**Spec:** `.docs/orag-decisions.md` (D-001…D-022) and the "v0.2" roadmap in `.docs/plans/2026-10-01-orag-v0.1-implementation-plan.md`. Scope review: `_jobs/review-2026-10-06-roadmap.md` (local, uncommitted) and the gpt-6-astra consultation of 2026-10-10 summarised under "Scope decisions" below.

**Interfaces:**
- Consumes: `isolate::parse_isolated_until(bytes, format, stop) -> Result<ParsedDocument>` (Task 23b), `exit::exit_without_native_teardown(code)`.
- Produces: `isolate::sys::{spawn_child(cmd: &mut Command) -> io::Result<Contained>, classify(status: ExitStatus) -> Failure}` with `Contained::{pid(&self) -> u32, exited(&mut self) -> io::Result<bool>, kill_tree(&mut self), wait(self) -> io::Result<ExitStatus>}` and `enum Failure { FileFault(String), Host(String) }`. **Order is fixed and keeps today's invariant (isolate.rs `waitid(WNOWAIT)` then `killpg`, Task 23b): `exited()` only probes and never reaps; the caller then always calls `kill_tree()` (group/job kill while the pid is still ours) and only then `wait()` reaps.** On unix `exited` = `waitid(P_PID, WEXITED|WNOHANG|WNOWAIT)`, `kill_tree` = `killpg(SIGKILL)` (fallback `kill`), `wait` = `Child::wait`; the existing code moves into `isolate/unix.rs` with exactly this behaviour and its tests. On Windows `exited` = `WaitForSingleObject(process, 0) == WAIT_OBJECT_0`, `kill_tree` = `TerminateJobObject`, `wait` = `Child::wait`. Unix and Windows modules expose the same names; `isolate.rs` uses only these.

Design (Windows):
- Child started with `CREATE_NEW_PROCESS_GROUP | CREATE_NO_WINDOW` so console Ctrl-C/Ctrl-Break never reaches it (the parent stops it).
- A Job Object per child with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE | JOB_OBJECT_LIMIT_PROCESS_MEMORY` (4 GiB, same as the Linux address-space cap) and `JOB_OBJECT_LIMIT_DIE_ON_UNHANDLED_EXCEPTION` (no WER dialog). The handle is not inheritable. Assigned right after spawn: the child reads stdin before doing anything and the parent writes stdin only after `AssignProcessToJobObject` succeeded, so the child cannot start descendants outside the job. Assignment failure kills the child and returns `Failure::Host` (fail closed).
- Kill = `TerminateJobObject` (kills descendants too). Parent death closes the job handle, and `KILL_ON_JOB_CLOSE` kills the child: this replaces the unix orphan watchdog on Windows.
- Exit classification: NTSTATUS crash codes `0xC0000005` (access violation), `0xC00000FD` (stack overflow), `0xC0000409` (fast fail / Rust abort), `0xC0000017` and `0xC000012D` (out of memory) → `FileFault`; any other non-zero exit → `Host` (same rule as unix: error exits are host problems).
- Shutdown signals: `tokio::signal::windows::{ctrl_c, ctrl_break, ctrl_close, ctrl_shutdown}`; any of them starts the graceful shutdown.
- Static CRT and CPU floor in `.cargo/config.toml`, so every build (CI, release.yml, a developer's machine) gets them: `[target.x86_64-pc-windows-msvc] rustflags = ["-C", "target-feature=+crt-static,+avx2,+fma,+f16c,+bmi2"]` and `[env] LLAMA_STATIC_CRT = "1"` (read only by llama-cpp-sys-2's Windows path). llama-cpp-sys-2 0.1.158 builds ggml with `GGML_NATIVE=OFF` and enables `GGML_AVX2/FMA/F16C` from `CARGO_CFG_TARGET_FEATURE`, so the rustflags are what turns the AVX2 kernels on (cl.exe ignores `-march`). A test step reads `target/release/build/llama-cpp-sys-2-*/out/build/CMakeCache.txt` and asserts `GGML_AVX2:BOOL=ON`, `GGML_NATIVE:BOOL=OFF`, `GGML_OPENMP:BOOL=OFF` (added to `scripts/check-llama-build.sh` for Windows). No OpenMP (feature off). CPU floor: x86-64 with AVX2/FMA/F16C/BMI2 (Intel Haswell 2013+, AMD Excavator/Zen); recorded in `platform-floors.sh` as `WINDOWS_CPU_FLOOR="avx2 fma f16c bmi2"` and in the README.

### Task 39: `suspicious_layout` advisory warning (0.2.0-alpha.16)

**Files:**
- Create: `crates/orag/src/ingest/layout.rs`
- Modify: `crates/orag/src/ingest/pdf.rs`, `crates/orag/src/ingest/mod.rs`, `docs/api.md`, `crates/orag/src/server/ui/documents.js` (warning label)
- Test: `layout.rs` tests, `pdf.rs` tests

**Interfaces:**
- Produces: `pub fn page_looks_broken(text: &str) -> Option<&'static str>` returning the reason (`"replacement characters"`, `"mostly single letters"`) or `None`; the PDF parser collects pages with a reason into one warning `suspicious_layout: page(s) 3, 7-9 may be extracted out of order or garbled (reason); answers from them can be wrong`.

Rules (each needs at least 200 non-space characters on the page, so short pages never trigger):
1. U+FFFD makes up ≥ 1 % of characters → `replacement characters` (missing ToUnicode maps).
2. ≥ 40 % of whitespace-separated tokens are a single letter (not digit) → `mostly single letters` (letters split by positioning).
Short lines alone are **not** a rule (tables, poems, code lists are legitimate).
