# v0.3 eval harness parity (step 55)

`orag eval retrieval` reported "in context" as "a label within the top 8 of
the fused list". The answer path (`AnswerEngine::answer`) does something else:
it retrieves `max_context_chunks × CANDIDATES_PER_SLOT` = 16 candidates and
`select_context` fills at most 8 prompt slots in fused order, skipping any
chunk that does not fit the answer model's token budget and taking a later
one instead. Step 50 showed how a mismatch between experiment and production
can turn a result around, so before the next ranking experiment (fusion
near-miss recovery) the harness should measure exactly what the model sees.

Chosen by the owner's protocol: Claude and `gpt-6-sol` (effort high) both
recommended this before any ranking change.

## Change

- `retrieval::answer::answer_context` exposes the production selection
  (`select_context` with the question's refusal sentence); `answer` and the
  eval both use it.
- The eval retrieves at least 16 candidates, chooses the prompt with
  `answer_context` and scores "in context" on the chosen chunks. Ranks,
  recall@k, MRR and nDCG are unchanged.
- The CLI loads the configured answer model only for its token counter. The
  report names it (`context_budget`) and counts skipped chunks per strategy
  (`skipped_chunks`).
- Tests: a chunk larger than a small fake generator's budget is skipped, so
  the question is no longer "in context" while recall stays the same; the
  pool size equals production's.

## Re-baseline (2026-10-14, 0.3.0-alpha.7 engine)

Release build, Apple M5 Max, default models (`qwen3-embedding-0.6b-q8_0`,
answer model `qwen3.5-4b-q4_k_m`), lexical `prefix:3+stem:7`.

| set | old harness (hybrid in context) | new harness | per question | skipped chunks |
|---|---|---|---|---|
| v02 (175 answerable) | 0.931 | 0.931 | identical (dev 0, holdout 0) | 0 |
| seed | 1.000 | 1.000 | identical | 0 |
| anayasa-tr | 0.950 | 0.950 | identical | 0 |
| anayasa-cekim-tr | 0.967 | 0.967 | identical | 0 |

Lexical and dense rows are identical too (v02: 0.754 and 0.891).

With the default 8 chunks of at most 512 tokens and the answer model's
context window, the budget never binds on these sets and the fused top 8 does
not depend on the retrieval depth, so every earlier "in context" number
stands. The harness now also holds for longer chunks, smaller answer models,
and experiments that reorder or filter the 16 candidates.
