# v0.3 bge-m3 re-measurement (step 59)

In Task 44 (`v0.2-model-decision.md`) `bge-m3-q8_0` was the strongest embedder candidate on
averages but missed the dev rule (+3 against ≥ 6) on the old v0.2 set; D-007 names it the first
candidate of the next model review. The set was rewritten since (step 49) and the engine changed
(cross-language fusion, prefix stems, headings), so this step measures it again on the current
engine. Measurement only: the default changes only if the rule below says so. gpt-6-sol (high)
recommended this before a reranker experiment (the model is local; a reranker would need a
download and new code), and the orchestrator agreed.

## Decision rule (written on 2026-10-14, before bge-m3 is scored on this engine)

It is not changed after the numbers are in. Task 44's embedder rule, unchanged, plus two
conditions on the answer context that the old rule did not have. `bge-m3-q8_0` replaces
`qwen3-embedding-0.6b-q8_0` only if, with hybrid retrieval on `eval/corpus/v02` +
`v02-retrieval.jsonl`, paired per question:

1. recall@10 wins minus losses ≥ 6 on **dev**;
2. recall@10 wins minus losses ≥ 0 on **holdout** (read once);
3. no category loses more than 2 questions net on recall@10 (dev and holdout together);
4. query-embedding p95 ≤ 2 × the current default's;
5. `orag serve` RSS after indexing grows by ≤ 1.5 GB;
6. hybrid in context (answer-path context, step 55) loses nothing net on dev and on holdout;
7. no category loses more than 2 questions net on in context (dev and holdout together).

The holdout was read in earlier steps on this set, so a pass here is not an independent
confirmation; it is recorded as such. Changing the embedder forces a reindex (D-007), which
the release note would have to say.

| # | Condition | Result | Pass |

| 4 | query-embedding p95 ≤ 2 × default | not measured (rule already failed) | – |
| 5 | serve RSS growth ≤ 1.5 GB | not measured (rule already failed) | – |

| 7 | no category loses > 2 on in context | all ≥ 0 | yes |

**Not adopted:** condition 1 fails by one question, as it failed by three on the old set. bge-m3
fixes both remaining multi-document misses (`v2-md-017`, `v2-md-018`) and several deep ones, so
it stays the first candidate of the v0.4 model review. Orchestrator and gpt-6-sol (high) both
recommended keeping the rule rather than waiving it: a change of embedder forces every user to
reindex, the holdout has been read in earlier steps, and conditions 4-5 are unmeasured. v0.4
should decide it with a new pre-registered rule, a fresh holdout and the cost measurements.
