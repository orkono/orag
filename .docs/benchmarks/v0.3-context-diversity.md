# v0.3 context diversity (step 50)

On the rewritten v0.2 set (`v0.3-set-rewrite.md`), with the 0.3.0-alpha.1
fusion, multi-document questions are the weakest category: hybrid in context
0.800, MRR@10 0.260 (the second document arrives late). Four of the nine dev
misses have their evidence at hybrid rank 9 or 10, just outside the 8-chunk
answer context. This step tries reorderings of the fused list that spread the
answer context over more documents or keep chunks both lists agree on.

## Decision rule (written on 2026-10-13, before any variant is scored)

It is not changed after the numbers are in.

Variants are scored with `orag eval retrieval` on `eval/corpus/v02` +
`v02-retrieval.jsonl`, default models, hybrid strategy. Tuning looks at the
**dev** split only; holdout is read once, for the chosen variant. Paired per
question on "in context", against 0.3.0-alpha.2.

The chosen variant replaces the current ordering only if:
1. wins minus losses ≥ 3 on **dev**;
2. wins minus losses ≥ 0 on **holdout**;
3. no category loses more than 2 questions net (dev and holdout together),
   and multi_document does not lose net;
4. `seed.jsonl`, `anayasa-tr.jsonl` and `anayasa-cekim-tr.jsonl` lose at most
   1 question net each on hybrid in context;
5. it adds no model call and no new index (ordering only).

Otherwise the current ordering stays and the result is recorded here.
`v02-answers.jsonl` is reported for the chosen variant, outside the rule.

## Result (2026-10-13): rejected, the ordering stays

Setup: release build on Apple M5 Max (Metal), default models, the rewritten
v0.2 set. Baseline (0.3.0-alpha.2): hybrid in context 0.909, multi_document
0.800 (MRR@10 0.260).

### Variants scored on dev

A reordering of the hydrated candidates, applied in the experiment *after*
`retrieve()` had cut the fused list to the caller's limit:

| variant | dev wins / losses (net) |
|---|---|
| at most 2 chunks per document in the first 8 | 0 / 2 (−2) |
| at most 3 or 4 per document | 0 / 0 (0) |
| chunks both lists rank within 5 or 10 move behind the #1s | 0 / 0 (0) |
| the same within 15 | 2 / 0 (+2) |
| the same within 20, 25, 30 or 50 (any chunk in both lists) | 3 / 0 (+3) |
| a 2- or 3-per-document cap with consensus within 10 | at most 0 |

"Any chunk in both lists right after the #1s" was chosen (no new constant)
and read once on holdout: 1 / 1 (0). The older sets did not lose
(anayasa-cekim-tr +1).

### Why it was rejected

The experiment reordered only within the top 10 candidates the eval harness
asks for, so its +3 came from moving ranks 9 and 10 into the first 8. The
answer path asks for exactly 8 candidates, so that reordering would not change
a single answer context. Implemented where it belongs (a consensus tier in
`promote_list_leaders`, over the whole fused list), the variant scored:

| | dev (net) | holdout (net) | hybrid in context | cross_language | multi_document |
|---|---|---|---|---|---|
| 0.3.0-alpha.2 | – | – | 0.909 | 0.880 | 0.800 |
| consensus tier | 3 / 4 (−1) | 2 / 4 (−2) | 0.891 | 0.680 | 0.650 |

Chunks that both lists rank in the middle push single-list #2-#4 hits, the
cross-language answers of step 48, out of the context. It fails rules 1 and 2
and multi_document loses 3, so the 0.3.0-alpha.1 ordering stays.

### What this says about multi-document questions

Ordering cannot fix them. Of the four multi_document misses, only md-012 has
both documents in any list's top 10. For md-007, md-017 and md-018 one half
of the question is not found even when asked on its own (analysis by the
orag-plan session: "Deniz Sulama iadelerinde" does not find the catalogue's
return clause; "mahkeme kararları için ne istiyor" does not find Anayasa
"kararları gerekçeli olarak yazılır"; "dinlenmeyi hak olarak tanıyor mu" does
not find "Dinlenmek, çalışanların hakkıdır"). These are single-passage recall
problems (inflection, long-document dilution), for a recall step, not a
context-ordering one.

Lesson for the next fusion experiment: apply a candidate reordering where
production applies it, before the cut to the caller's limit, and check that
the experiment and the final code score the same before reading holdout.
The step 48 experiment did reorder the fused list before that cut, and its
final code scored the same as the experiment, so the 0.3.0-alpha.1 decision
stands.
