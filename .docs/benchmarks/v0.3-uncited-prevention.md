# Preventing uncited answers (step 68): not pursued

Date: 2026-10-15, main at `0.3.0-alpha.21`. Decision agreed with gpt-6-sol (high).

Step 67 marks an answer that is not an abstention and cites no valid source
(`"uncited": true`). Step 68 was to prevent such answers at generation time,
either with a stronger citation rule in the system prompt or with a retry.

## The target, counted

Default configuration (`qwen3-embedding-0.6b-q8_0`, `qwen3.5-4b`, sampler `dry`):

| Set | Answers | Uncited |
|---|---|---|
| `v02-answers` (dev and holdout) | 60 | 0 |
| `answers-anayasa-tr` | 10 | 0 |
| `answers-ceza-tr` | 9 | 0 |
| `v04-holdout-answers` (read in step 66) | 30 | 1 (`v4-ans-019`, also wrong) |

The only target is in a holdout that must not be tuned on, so no prompt or
retry variant can be judged: there is nothing to gain on dev.

## Why not anyway

- The system prompt already requires a citation for every claim.
- A prompt change affects every answer; without a dev target the change can
  only be measured for harm, not for benefit.
- Answers stream token by token before citations are checked, so a retry would
  need a new stream event that replaces text already shown (an API change).

## Outcome

No code change. The step 67 notice stays as the mitigation. Uncited answers and
`v2-ans-047` (the model lists rules instead of answering) wait for a larger
answer dev set in v0.4, where both can be measured. A zero count on these sets
is not evidence that the risk is zero.
