# v0.3 fusion near misses: a 10-chunk answer context (step 57)

On 0.3.0-alpha.9 the v0.2 set misses 8 of 89 dev questions (hybrid in
context 81/89, scored on the real answer context since step 55). Four are
near misses: one list ranks the evidence 5th to 7th, but fusion leaves it
out of the 8-chunk context.

| question | hybrid | lexical | dense |
|---|---|---|---|
| `v2-xl-021` | 26 | – | 6 |
| `v2-md-018` (label 0) | 16 | 5 | 30 |
| `v2-tab-011` | 11 | 13 | 5 |
| `v2-acc-007` | 11 | 7 | 26 |

The other four are deep (best list rank 9 to 32) and need recall work.

The 8 slots are filled by each list's top 4 (D-005, step 48), so a hit at
rank 5 or below in only one list can only get in when the leaders overlap.
This step tries a larger context: **10 chunks**, so 5 leaders per list
(`max_context_chunks` 8 → 10; the candidate pool follows, 16 → 20).

Chosen by the owner's protocol. Claude first proposed this together with a
round-robin tail after the leaders; `gpt-6-sol` (effort high) pointed out
that with 4 + 4 distinct leaders a reordered tail cannot change the eight
selected chunks, so only the 10-chunk context is scored. Claude agrees.

Baseline engine: 0.3.0-alpha.9 (`e7fb786`): fusion of step 48, lexical
`prefix:3+stem:7`, headings of step 52, budgeted eval context of step 55.

## Decision rule (written on 2026-10-14, before the variant was scored)

This rule is not changed after the numbers are in. There is one variant; it is
scored on **dev** first, and holdout is read once only if dev passes.

The 10-chunk context replaces 8 only if all of these hold:

1. hybrid in context (budgeted answer context), wins minus losses ≥ **+2** on
   dev, paired per question against alpha.9;
2. holdout wins minus losses ≥ 0 (read once, after rule 1 passes);
3. no category loses more than 2 questions net (dev and holdout together);
4. `seed.jsonl`, `anayasa-tr.jsonl` and `anayasa-cekim-tr.jsonl` lose at most
   1 question net each;
5. answers (`v02-answers.jsonl`, default sampler): expected facts and valid
   citations do not fall; every probe that changes is read against its
   answer and cited sources, and no changed probe gains an unsupported claim;
   abstention precision and recall are reported;
6. answer latency p50 rises by at most 20% (p95 reported).

If any rule fails, the context stays at 8 and the result is recorded here.

## Result (2026-10-14): rejected, the context stays at 8 chunks

Release build, Apple M5 Max, default models, alpha.9 engine with
`max_context_chunks` set to 10 by an experiment switch (not committed).

| rule | result | pass |
|---|---|---|
| 1. dev net ≥ +2 | +2 (`v2-md-018`, `v2-tab-011`), no loss | yes |
| 2. holdout net ≥ 0 (read once) | 0 | yes |
| 3. no category below −2 net | multi_document +1, table +1, others 0 | yes |
| 4. older sets ≥ −1 each | seed 0, anayasa-tr 0, anayasa-cekim-tr +1 (29/30 → 30/30) | yes |
| 5. answers: no fall, no unsupported claim | expected facts 0.950 = 0.950, valid citations 1.000 = 1.000, cited evidence 0.975 → 1.000; but `v2-ans-051` (unanswerable: which shipping company) now answers "Kuzey Lojistik A.Ş.", the employer named in the HR handbook, not a shipping company: an unsupported claim. Abstention P / R 0.941 / 0.800 → 1.000 / 0.700 | **no** |
| 6. answer p50 latency ≤ +20% | 1044 → 1441 ms (**+38%**); p95 2612 → 2873 ms | **no** |

Retrieval gains (hybrid in context 0.931 → 0.943, no chunk skipped by the
budget) come with a longer prompt: answers are 0.4 s slower at the median,
and the wider context lets the model pull an unrelated company name into an
answer it should refuse. Five probes changed: `v2-ans-011` (now answers
"10 iş gündür" instead of a hedged refusal) and `v2-ans-016` (both units)
improved, `v2-ans-015` lost the "24 ay" half, and two unanswerable probes
(`v2-ans-051`, `v2-ans-055`) stopped refusing.

**Deviation.** When the dev result was printed, the comparison script also
printed whole-set hybrid in context, which includes holdout, before holdout
was read on its own. The decision does not depend on that number (rule 2
was 0 and the variant fails rules 5 and 6), but holdout was not unseen.

The four near misses stay. A recovery that does not lengthen the prompt (for
example, replacing the weakest leader rather than adding slots) would be a new
step with its own rule.
