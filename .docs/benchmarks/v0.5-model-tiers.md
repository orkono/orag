# v0.5 generator tiers for the setup page

Step 81. The setup page will measure the machine and offer the generators
that fit it (owner request, 2026-10-20). The embedder stays
`qwen3-embedding-0.6b-q8_0`; only the generator is a choice. This page
decides which generators may be offered and records how much memory each one
needs, so the page can say honestly whether a model fits.

Plan agreed by muse and approved by gpt-6-astra (two rounds, 2026-10-20). The
owner accepted the exception for weak machines: where only one tier fits, the
page offers that one with a warning; where none fits, it says the machine is
not supported.

## Decision rule (written on 2026-10-20, before any candidate is scored)

Scored with `orag eval answers` on `eval/datasets/v02-answers.jsonl`, **dev
split only** (40 probes), the served sampler, on the Mac (Metal), against the
default `qwen3.5-4b-q4_k_m` measured in the same run. A candidate tier is
offered only if all hold:

1. valid citations >= 0.95;
2. uncited answers <= 1;
3. expected facts >= default - 0.10;
4. abstention recall >= default - 0.10;
5. abstention precision >= default - 0.10 (a model that refuses everything
   does not pass on recall alone).

Reported, not gated: the Turkish-subset expected facts (dev probes with
`lang = "tr"`), the v02 holdout split once for the candidates that pass, and
p50/p95 answer latency.

A candidate that fails is not shipped. If the small tier fails, the page has
no small tier and machines below the default's need get the "not supported"
message (the owner's exception). The default is not re-decided here.

## Memory and speed (measured, not estimated)

For every tier that passes, during the answer runs:

- **Peak resident memory** of the whole `orag` process (generator + embedder
  + app + llama.cpp buffers; on Metal the process footprint, counted once) at
  the production context and batch, one generation at a time with the
  embedder loaded. Measured on the Mac (`/usr/bin/time -l`, max RSS and peak
  footprint) and on the Linux CPU reference.
- **Need** shown by the page = measured peak + 2 GB OS headroom, rounded up to
  the next 0.5 GB. A tier fits when total RAM >= need; disk fits when free
  space >= embedder + generator + 512 MB.
- **Speed hint**: prompt processing and generation tokens per second at
  production settings on both references, shown as labelled estimates.
