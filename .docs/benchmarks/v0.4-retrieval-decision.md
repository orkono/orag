# v0.4 retrieval decision: embedder and reranker (step 63)

Plan: `.docs/plans/2026-10-14-orag-v0.4-reranker-plan.md`, Task 6. One rule decides the embedder
(bge-m3, step 59) and a reranker (step 62) together, with a single read of the fresh v0.4
holdout (D-018, step 60). The orchestrator proposed the rule; gpt-6-sol (high) asked for four
changes, all taken (1: bge-m3 alone keeps its old gate; 2: latency at the chosen variant;
3: memory measured on `orag serve`; 4: no new unsupported answer or invalid citation).

## Decision rule (written on 2026-10-14, before any combination is scored)

It is not changed after the numbers are in.

**Runs.** Embedder {`qwen3-embedding-0.6b-q8_0` (default), `bge-m3-q8_0`} × reranker {none,
`qwen3-reranker-0.6b-q8_0`, `bge-reranker-v2-m3-q8_0`} × (rerankers only) {after promotion,
leaders pinned} × depth {16, 20, 30}: 26 runs of `orag eval retrieval` on `eval/corpus/v02` +
`v02-retrieval.jsonl`, context budget on (answer-path "in context", step 55), default lexical mode.
Only `dev` rows are read until a combination is chosen.

**Choice.** The combination with the highest v0.2 dev hybrid in-context wins minus losses against
the default (qwen3-embedding, no reranker), paired per question. Ties: no reranker before a
reranker, the smaller depth, the default embedder.

**Gates.**
- bge-m3 **without** a reranker keeps Task 44's gate: recall@10 dev W−L ≥ 6 (it measured +5 in
  step 59, so it cannot be chosen alone by this run).
- Any combination with a reranker: in-context dev W−L ≥ 4.

**Adopted only if, for the chosen combination:**
1. its gate above holds;
2. `v04-holdout-retrieval.jsonl`, read once: in-context W−L ≥ +1;
3. no category loses more than 1 net (v0.2 dev + v04 holdout);
4. factual + identifier + table lose nothing net (same scope);
5. `seed`, `anayasa-tr`, `anayasa-cekim-tr` lose at most 1 each (in context);
6. added hybrid retrieval p95 at the chosen depth and leader mode (with minus without the
   reranker, same embedder) ≤ 150 ms on this M-series Mac (Metal); with an embedder change, the
   full retrieval p95 against today's default is reported too. The CPU budget (≤ 1500 ms on the
   8-core x86-64 reference) cannot be measured now: if every other condition passes the change
   ships **opt-in** until that number exists; a default needs it;
7. `orag serve` with the chosen models loaded, RSS after indexing `eval/corpus/v02`, grows by
   ≤ 1 GB against the default;
8. answers (`--sampler dry`) on `v02-answers.jsonl` and `v04-holdout-answers.jsonl`: expected facts
   lose nothing net after a per-probe review of scorer artefacts, and no probe gains an unsupported
   answer or an invalid citation.

An embedder change forces a reindex, which the release note must say. Otherwise everything stays
as served and the result is recorded here.
